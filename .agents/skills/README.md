# Installed skills — generated, not authored

Every directory here is an **installed copy** placed by `bun run skills:install` (which drives `bunx skills add` for each skill and normalizes `skills-lock.json`), and `.claude/skills/<name>` is a symlink pointing back into this directory so Claude Code and Codex read one copy rather than two that drift. Nothing here is edited by hand: edit the source, re-run `bun run skills:install`, and commit the regenerated copy. The install script ends with a reconciliation check that fails when a skill is recorded in `skills-lock.json` but not installed here (or the reverse) — a locked-but-missing skill is a skill no agent ever reads, which used to fail silently.

Two kinds of skill live side by side, and `skills-lock.json` is how you tell them apart. A `"sourceType": "local"` entry points at `packages/skills/<name>` in this repo — that is **Fluncle's own doctrine**, authored here and canonical there. Every other entry records an upstream repository (`"sourceType": "github"`, e.g. `vercel-labs/agent-skills`, `resend/resend-skills`, `pbakaus/impeccable`) — that content is **vendored third-party work, redistributed under its own licence**, and upstream is where fixes belong. When reading this directory as an outside observer: the first kind tells you how Fluncle works, the second only tells you which community skills Fluncle installed.
