# Naming Conventions

Convention B is Fluncle's canonical cross-surface naming convention. The oRPC contract registry is the source of truth, and coverage tests require every route to carry a contract and operation name.

The scope is the _names a human or agent types or reads_: CLI commands and flags, HTTP API route paths and OpenAPI `operationId`s, MCP/WebMCP tool names, the SSH terminal's deep-link commands and menu, and the admin board's user-facing action verbs. It is not about internal function names, database columns, or component names — except where those leak into a public name.

This convention is subordinate to the voice canon. Where consistency would fight Fluncle's voice (`packages/skills/copywriting-fluncle`, `VOICE.md`), the voice wins and the convention bends. See [§5 Voice boundary](#5-voice-boundary).

### 1.3 MCP / WebMCP tools

`SHARED_TOOL_SPECS` is the canonical tool inventory. Read its `transports` values or `tools/registry.test.ts` for the per-surface sets. The archive operations are `list_findings`, `list_tracks`, and `search_archive`.

Beyond tools, the server MCP also serves **resources** (the archive as a corpus — `fluncle://finding/<logId>`, `fluncle://mixtape/<logId>`) and Fluncle-voiced **prompts** (`recommend_finding`, `walk_recent_night`, `decode_coordinate`), named `verb_noun` like the tools. Both are server-MCP only: `navigator.modelContext` has no resource/prompt primitive, so the browser WebMCP surface mirrors the tool set alone.

### 1.4 SSH (`apps/ssh`)

Two naming surfaces: the **deep-link command argument** (`ssh rave.fluncle.com <arg>`) and the **menu items**.

Deep links (`parseBootCommand`): `latest`, `fresh`, `random`, or a bare Log ID coordinate (e.g. `004.7.2I`, `019.F.1A`). Lowercase, single words.

Menu item labels (`menuItems()`, 12 items): `Latest findings`, `Fresh releases`, `Artist archive`, `Sonic galaxies`, `Mixtape archive`, `Random banger`, `Submit a track`, `Subscribe`, `Install CLI`, `System status`, `About`, `Quit`. Sentence case, in-fiction nouns. `Sonic galaxies` opens the browse-by-feel galaxies screen (list + open, cloning `Artist archive`); it reads the same public `list_galaxies`/`get_galaxy` ops the CLI's `fluncle galaxies [slug]` does, so the operation reads the same across CLI, API, and SSH.

Note the deep-link `latest` maps to the CLI's `recent`, the API's `listFindings` (`GET /findings`), and the MCP's `list_findings` — **four names for one read**, all naming the found-order feed after the vocabulary cut.

### 1.5 Admin board (user-facing verbs)

The web admin board (`apps/web/src/components/admin/*`, `apps/web/src/routes/admin/*`) labels actions in plain operator English, which is a different register again:

- Enrich: `Run enrichment` / `Retry enrichment` / `Re-run enrichment` / `Enrich`
- Publish: `Post to {platform}` / `Re-post` / `Push draft to inbox` / `Re-push draft` / `Push` / `Mark live` / `Mark failed` / `Drafted` / `Live`
- Note: `Save note` / `Save & next`
- Mixtape/plan: `Add to a plan` / `New plan` / `Discard plan` / `Make YouTube public`

The same publish action is `Push draft to inbox` (board) / `admin track draft` (CLI) / `POST …/social/{platform}/draft` (API). The same enrichment work is `Run enrichment` (board) / `admin tracks enrich --queue` (CLI, a worklist view — the sweep itself is the on-box cron) / `GET /admin/tracks/work` (API). The board verbs are fine as voice (they're crew-facing copy), but they're not derivable from the CLI/API name and vice versa.

## 3. Adopted projection rules

Convention B projects each operation from one fixed registry name:

- **Canonical operation:** use `verb_noun` with a singular machine noun. MCP and WebMCP tools use that `snake_case` name verbatim.
- **OpenAPI:** derive the `operationId` by recasing the canonical operation to camelCase, such as `list_tracks` → `listTracks`.
- **API:** use plural REST resources such as `/tracks`, `/submissions`, and `/editions`; keep true singletons such as `/me`, `/auth`, and `/newsletter` singular. Use the HTTP method as the verb, and put a non-CRUD action at `POST /{resource}/{id}/{action}` with one lowercase action word.
- **Public CLI:** keep spoken public actions as bare root verbs such as `submit`, `subscribe`, `random`, `recent`, and `open`, and map each one explicitly to its canonical operation.
- **Admin CLI:** use plural groups followed by the verb, such as `admin tracks update`, `admin tracks enrich`, `admin tracks draft`, and `admin submissions approve`.
- **SSH:** keep in-fiction labels and deep links such as `latest` and `Random banger`, and register each as an explicit alias of its canonical operation.
- **Worklists:** expose a verb worklist through `--queue` on that verb, such as `tracks enrich --queue`, `tracks observe --queue`, or `tracks context --queue`; do not add dash-compound `*-queue` commands.

## 5. Voice boundary

The voice canon (`VOICE.md`, `packages/skills/copywriting-fluncle/references/voice.md`) governs **human, crew-facing copy**. Naming consistency must not overwrite it. The boundary, stated as a rule:

- **Machine-facing names** (CLI command/flag identifiers, API paths, `operationId`s, MCP tool names) use the plain machine noun `track` and a closed verb set. These have "no crew in the room" — the Narrator rule says keep them honestly-plain. This is where the convention applies in full.
- **Human-facing copy** on any surface (CLI help text and output prose, SSH menu labels and detail screens, admin board action labels, empty states, confirmations) uses the voice nouns — `finding`, `banger`, `recovered`, `certify`, `Fluncle's Findings` — under the Garnish Rule (Earth verbs, cosmic trim; the cosmos modifies, never replaces the verb in functional controls). The convention does **not** force these toward the machine noun.
- The seam runs **per token, not per surface.** The CLI has both: the command identifier `recent` is machine-facing (lives in the registry), while its description "The latest bangers, newest first" is voice. The SSH deep-link `latest` is a machine token (a registered alias of `list_tracks`); the menu label `Latest findings` is voice. Keeping them in the registry as aliases is what makes the mapping explicit instead of accidental.

So the convention's job at the boundary is narrow: make every _machine_ name derivable from one registry, and record each _voice_ alias (`recent`, `latest`, `Random banger`) against its canonical op so nobody has to reverse-engineer which screen calls which endpoint.

## 6. How to name a new feature (checklist)

When you add a public operation — a CLI command, an API route, an MCP tool, an SSH deep link, or an admin action — name it once, then derive:

1. **Pick the canonical op:** `verb_noun`, where `verb` is in the closed set (`list`, `get`, `read`, `search`, `submit`, `subscribe`, `create`, `update`, `set`, `delete`, `publish`, or a named non-CRUD action like `enrich`/`observe`/`draft`/`distribute`/`finalize`/`requeue`/`purge`/`capture`/`crawl`/`backfill`/`resync`/`resolve`/`migrate`/`rank`/`drip`/`advance`/`build`/`merge`/`revoke`) and `noun` is the singular machine noun (`track`, `mixtape`, `submission`, `newsletter`, `preview`, `post`). `read` is reserved for a composite diagnostic resource whose one response intentionally combines raw rows with aggregates (`read_run_ledger`); use `list` for an ordinary entity collection and `get` for one entity. `set` writes an operator flag/kill-switch on the `settings` KV — `set_capture_budget`, `set_clip_drip`, `set_anchor_search`, `set_anchor_apify`. `revoke` un-issues a credential already handed out — `revoke_admin_grants` bumps the grant epoch so every outstanding admin browser cookie stops verifying. Add it to the registry.
2. **Derive the names, don't invent them:**
   - MCP/WebMCP tool = the op verbatim, `snake_case` (`search_archive`). Add the spec to `SHARED_TOOL_SPECS` (`apps/web/src/lib/server/tools/specs.ts`) with its `transports`, and both MCPs plus ChatDnB project it — never hand-write a tool into `mcp.ts` or `webmcp.ts`.
   - OpenAPI `operationId` = the op, `camelCase` (`searchArchive`).
   - API = REST: `{METHOD} /{resource}` for CRUD; `{POST} /{resource}/{id}/{action}` with a **single-word** action for non-CRUD. No dash-compound path segments.
   - Public CLI = bare verb at root if it's a spoken public action (`submit`); else `group noun-verb` under `admin` with **plural** groups (`admin tracks enrich`).
   - SSH deep link / menu label = whatever the voice wants — but **register it as an alias** of the canonical op.
3. **Check pluralization:** CLI groups are plural (`tracks`, `mixtapes`, `submissions`). Singular only for a true singleton (`me`, `auth`).
4. **No new dash-compound command/op names.** If you reach for `foo-bar`, it's usually `group` + `foo bar` (CLI) or a resource + action (API). Reserve kebab-case for flags and multi-word path _resources_ that are genuinely one noun. A **worklist view** of a verb is the canonical example: it is a `--queue` flag on the verb (`tracks enrich --queue`, `tracks observe --queue`, `tracks context --queue`), never a `verb-queue` command. The next worklist view (`render --queue`, …) follows the same shape.
5. **Keep the machine noun out of voice copy and the voice noun out of machine names** (§5). The identifier is `track`; the help text and labels can say `finding`/`banger`.
6. **Document it the moment it ships:** every public API route gets an `operationId` and lands in the OpenAPI spec; every MCP tool gets a `title`; every CLI command gets a one-line voice description. A route with no `operationId` is invisible to agents — treat that as a bug.
7. **Run a voice pass** (`copywriting-fluncle`) on the human-facing strings, separately from the machine name.

## 7. Local-exec ops (the registry's non-HTTP tail)

Most canonical ops project onto an HTTP surface, so the oRPC contract registry (`packages/contracts/src/orpc`) is their source of truth. A few operations are **local orchestrations** — they run on the operator's own machine and drive local processes (spawn a browser, hold `caffeinate`, read an audio device) rather than call the Worker. These are still named `verb_noun` and registered here, but they have **no oRPC contract and no `operationId`**. A local-exec op MAY carry a top-level `fluncle` CLI verb when it is the operator's daily driver (the command spawns local processes and never talks to the Worker) — the `admin` group stays reserved for authenticated Worker authority. Their primary surface is a package script or launcher; this table is their registry.
