# fluncle-device-mirror-timer — the shared device-replica mirror

The host trigger for the hourly, zero-LLM device mirror. [`device-mirror.sh`](../scripts/device-mirror.sh) runs the baked [`device-mirror.ts`](../scripts/device-mirror.ts), reads the production database with `TURSO_DATABASE_URL` plus a read-only `TURSO_AUTH_TOKEN`, and diffs the anchored allowlisted cut into the one shared device database identified by `DEVICE_TURSO_DATABASE_URL` plus its write-scoped `DEVICE_TURSO_AUTH_TOKEN`. It applies dependent-first deletes and then parent-first upserts inside the existing schema, releasing departed unique slugs and Log IDs before their replacements land, then updates `device_sync_meta` last. It never drops or recreates a data table: rebuilding would reset the libSQL replication log and make every device download the full database again.

Overlap is guarded twice: systemd does not start a second instance of an already-active oneshot, and the sweep acquires an atomic directory lock before reading either database. A lock older than two cadences is treated as stale after a crashed process. The summary is emitted through [`cron-output.sh`](../scripts/cron-output.sh) under `cron.device-mirror`; its `queueDepth` is the measured drift before, during, or after the run rather than a fixed success value.

## Activation is operator-gated

The repo half deliberately does not create a Turso database, provision credentials, or enable a timer. Before activation, the operator must create the derived database at the code's exact `device_sync_meta.schema_version`, provision the four source/target URL and token variables in the box's shared secrets file with the source token read-only and the target token write-scoped, rebuild the Hermes image so the script and its shared whitelist/selection modules are baked, and then run the repository's `install-host-timers.sh`. A first attended service tick must finish with `errors: 0`, `queueDepth: 0`, and a moving `produced` count when drift exists.
