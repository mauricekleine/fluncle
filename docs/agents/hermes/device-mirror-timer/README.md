# fluncle-device-mirror-timer — the shared device-replica publisher

The host trigger for the hourly, zero-LLM device publisher. [`device-mirror.sh`](../scripts/device-mirror.sh) runs the baked [`device-mirror.ts`](../scripts/device-mirror.ts), explicitly syncs the production database once into a persistent local embedded replica, and closes the sync client before any SQLite reader opens the file. The anchored IDs are selected into one local TEMP relation; every allowlisted tracks/findings/edges/entity copy, count, closure proof, and fingerprint then reads local storage. A corrupt or incomplete replica/generation is discarded and rebuilt automatically, while `DEVICE_MIRROR_FULL_REBUILD=true` is the explicit convergence escape hatch.

The verified local generation is uploaded to bounded, restart-checkpointed target staging tables. Staging row counts, every copied pointer, and a canonical typed-row fingerprint are proven before publication. A fixed server-local delta measurement then precedes one transaction containing dependent-first deletes, parent-first deterministic upserts, and the `device_sync_meta` fingerprint cutover. Upload/build/cutover failures cannot expose partial live rows; a lost response after commit is recognized as an idempotent replay on restart. Staging cleanup happens only after live counts, closure, version, and fingerprint metadata validate, and the live tables are never dropped or recreated, preserving libSQL replication history.

Overlap is guarded twice: systemd does not start a second instance of an already-active oneshot, and the sweep acquires an atomic directory lock before syncing either database. A lock older than two cadences is treated as stale after a crashed process. Persistent state lives below the cron user's home by default and contains the source replica plus the last verified generation. The bounded ledger summary under `cron.device-mirror` reports the replication frame/delta, drift age/backlog, staging checkpoint/generation, rebuild cause/duration, row/byte totals, artifact version, peak buffered rows/local disk, and validation result.

## Activation is operator-gated

The repo half deliberately does not create a Turso database, provision credentials, or enable a timer. Before activation, the operator must create the derived database at the code's exact `device_sync_meta.schema_version`, provision the four source/target URL and token variables in the box's shared secrets file with the source token read-only and the target token write-scoped, rebuild the Hermes image so the native embedded-replica client plus canonical deriver are baked, and then run the repository's `install-host-timers.sh`. A first attended service tick must finish with `errors: 0`, `queueDepth: 0`, `validation: "verified"`, and a moving `produced` count when drift exists.
