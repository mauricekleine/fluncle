# fluncle-device-mirror-timer — the shared device-replica publisher

The host trigger for the hourly, zero-LLM device publisher tick. The replica is what the live mobile app's offline-first store pulls, so freshness is a product property: the tick publishes once the live replica is older than `DEVICE_MIRROR_PUBLISH_INTERVAL_MS` (default 1 h) and otherwise reports `gateState: "paused"` with the replica's age, costing no sync, no derivation and no writes. `DEVICE_MIRROR_FULL_REBUILD=true` forces a publish. [`device-mirror.sh`](../scripts/device-mirror.sh) runs the baked [`device-mirror.ts`](../scripts/device-mirror.ts), explicitly syncs the production database once into a persistent local embedded replica, and closes the sync client before any SQLite reader opens the file. The anchored IDs are selected into one local TEMP relation; every allowlisted tracks/findings/edges/entity copy, count, closure proof, and fingerprint then reads local storage. A corrupt or incomplete replica/generation is discarded and rebuilt automatically, while `DEVICE_MIRROR_FULL_REBUILD=true` is the explicit convergence escape hatch.

## What a publish writes

A publish writes only the rows that drifted. The verified local generation and the live target are walked together in primary-key order — the generation streams off local disk, the target is read one bounded keyset page at a time — and two rows are equal when their digests agree. The digest is derived from `DEVICE_DB_COLUMNS` and the same canonical encoding the generation fingerprint uses, so a column added to the allowlist enters the comparison automatically and a target whose stored columns disagree with the allowlist is rejected before the walk starts. Every local row also feeds a projected fingerprint, the generation's own fingerprint recomputed from the rows the walk actually saw; a disagreement is a walk that skipped or double-counted a row and falls back rather than ships. The resulting inserts, updates and deletes land in ONE target transaction — dependent-first deletes, parent-first upserts, the `device_sync_meta` fingerprint cutover — exactly as the whole-generation cutover does, so a device reads the old complete generation or the new complete generation and the watermark says which. The run summary reports `publishPath` (`delta` / `rewrite` / `replay`), `rewriteReason`, `deltaRows` and `produced` (rows written), so the ledger shows which path a tick took.

The staged whole-generation rewrite is the fallback, and the `rewriteReason` names why it was taken: `schema_change` (the stage shape no longer matches the shipped column list, so the live rows are of the old shape), `no_prior_generation` (the target carries no content fingerprint to diff against), `delta_over_threshold` (more drift than one transaction should carry — `DEVICE_DELTA_MAX_SHARE` of the generation, capped at `DEVICE_DELTA_MAX_ROWS`; the walk abandons itself the moment the ceiling is crossed, so an over-threshold tick pays a partial read rather than a wasted full one), or `delta_validation_mismatch`. On that path the generation is uploaded to bounded, restart-checkpointed target staging tables; staging row counts, every copied pointer, and a canonical typed-row fingerprint are proven before publication, and a fixed server-local delta measurement precedes the cutover transaction.

Neither path can expose partial live rows, and a lost response after commit is recognized as an idempotent replay on restart. Staging cleanup happens only after live counts, closure, version, and fingerprint metadata validate, and the live tables are never dropped or recreated, preserving libSQL replication history.

`bun run --cwd apps/web scripts/db-performance/device-resources.ts --profile <1x|2x>` is the local resource proof. It materializes the manifest cardinality with 4,096-byte embeddings, proves the source census and initial source-file fingerprint, and drives the real local sync, checkpoint, anchored derivation, staged publication, full-rebuild, corrupt-replica, and interrupted-stage recovery paths. Each lifecycle window records its own start and completion before the next phase begins, and direct target row-count/watermark parity follows incremental refresh, full rebuild, and both recovery paths. It reports the OS-process RSS high-water separately from sampled heap and RSS, a real nonzero local WAL before the production checkpoint and zero WAL after it, semantic candidate/last-verified generation overlap, target-stage disk, and aggregate temporary disk. The aggregate sample covers the complete directory awaited before atomic rename while the populated derivation `.tmp`, target files and sidecars, and prior generation coexist; semantic overlap labels remain limited to the candidate and last verified generations. Its source sync is an explicit local file-copy stand-in and its target is local Bun SQLite, so it measures neither production/hosted-libSQL behavior nor network replication latency; each reported window has one sample and is compared separately with the 3,430-second service deadline.

Overlap is guarded twice: systemd does not start a second instance of an already-active oneshot, and the sweep acquires an atomic directory lock before syncing either database. A RUNNING tick touches its own lock every minute, so the stale window (`DEVICE_MIRROR_LOCK_STALE_MS`, default 15 minutes) bounds how long a lock left by a DEAD tick blocks its successors rather than how long a publish may take — and the tick releases its lock on SIGTERM/SIGINT/SIGHUP, which is the death the admission runner's containment deals when it fences a lease.

## Activation is operator-gated

The repo half deliberately does not create a Turso database, provision credentials, or enable a timer. Before activation, the operator must create the derived database at the code's exact `device_sync_meta.schema_version`, provision the four source/target URL and token variables in the box's shared secrets file with the source token read-only and the target token write-scoped, rebuild the Hermes image so the native embedded-replica client plus canonical deriver are baked, and then run the repository's `install-host-timers.sh`. A first attended service tick must finish with `errors: 0`, `queueDepth: 0`, `validation: "verified"`, and a moving `produced` count when drift exists.
