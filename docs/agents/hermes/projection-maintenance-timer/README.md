# Runtime projection maintenance timer

`fluncle-projection-maintenance` is the permanent five-minute convergence loop for track due-work, crawl due-work, public aggregates, and artist qualification after their respective cutovers open. Each firing enters database admission and reads bounded projection status exactly once. Track and crawl advance only when their repair totals are nonzero; the public families also advance for an epoch mismatch, and public aggregates advance for an invalid anchor document.

The payload is fixed, serial, and bounded. It visits `track_due_work`, `crawl_due_work`, `public_aggregates`, then `artist_qualification`; no family overlaps another. Every advance uses `--action repair --limit 500`. Track and crawl receive `--max-steps 20`, which lets one firing consume up to twenty durable pages while preserving the server's five-marker cap for multiplicative track fanout; the public families retain `--max-steps 4`. Spending a budget is a healthy incomplete result, and the next firing resumes the database-owned marker set or cursor. A marker written during a pass is consumed by the remaining budget when the target's final indexed debt probe sees it; a marker written after that probe remains durable for the next firing.

The timer is default-dark per cutover. With every cutover dark it performs one status read, reports `gateState: "disabled"`, and issues no advance. A dark family stays untouched when another family is open, and an open family with zero debt also issues no advance. Installation cannot open a cutover or change read routing. The summary reports inspected families, processed subjects, gate state, per-family completion, and errors; it deliberately omits `queue_depth` because status uses capped probes and cannot prove an exact remaining depth.

Rebuild, exact audit, and every cutover change remain attended operator operations. The agent token can read bounded status and invoke only the bounded repair action for the four runtime families. It cannot rebuild, audit, mutate a cutover, select another target, change the page limit above the server maximum, or bypass the authenticated control plane.

The service is a one-shot unit, and systemd keeps its timer in the running state until that invocation becomes inactive, so timer firings cannot overlap the same service. Database admission additionally serializes it against other recurring writers. Admission has a 120-second ceiling; the one status process and four possible family processes each have a 120-second ceiling; `TimeoutStartSec=730` covers that 720-second maximum plus fixed process overhead. A timeout is a failed bounded tick rather than a lost cursor: server mutations are page-atomic and the next activation resumes durable debt.

The sweep is visible as `cron.projection-maintenance` on `/status` and as `projections.repair` in the run ledger/admission registry. Install or refresh it through the roster-derived [`../install-host-timers.sh`](../install-host-timers.sh). Rollout is image first, then timer installation, then an attended service start while every cutover is dark; verify a disabled ledger row before relying on the recurring schedule. Roll back by disabling the timer. If projected reads must roll back too, the operator separately closes the affected cutover; never grant the recurring sweep that authority.
