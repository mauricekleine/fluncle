# Runtime projection maintenance timer

`fluncle-projection-maintenance` is the permanent five-minute convergence loop for track due-work, crawl due-work, public aggregates, and artist qualification after their respective cutovers open. Each firing enters database admission and reads bounded projection status exactly once. Track and crawl advance only when their repair totals are nonzero; the public families also advance for an epoch mismatch, and public aggregates advance for an invalid anchor document.

The payload is fixed, serial, and bounded. It visits `track_due_work`, `crawl_due_work`, `public_aggregates`, then `artist_qualification`; no family overlaps another. Every advance uses `--action repair --limit 500 --no-terminal-status`. The automation-only flag is accepted by the CLI only for JSON repair commands: each request still passes `includeStatus: false` through the authenticated admin contract, but the CLI does not follow the bounded step sequence with another global status read. The tick therefore pays exactly one global status suite, at its opening gate. Track and crawl receive `--max-steps 20`, which lets one firing consume up to twenty durable pages while preserving the server's five-marker cap for multiplicative track fanout; the public families retain `--max-steps 4`. Spending a budget after processing pages is a healthy incomplete result, and the next firing resumes the database-owned marker set or cursor. A marker written during a pass is consumed by the remaining budget when the target's final indexed debt probe sees it; a marker written after that probe remains durable for the next firing.

The timer is default-dark per cutover. With every cutover dark it performs one status read, reports `gateState: "disabled"`, and issues no advance. A dark family stays untouched when another family is open, and an open family with zero debt also issues no advance. Installation cannot open a cutover or change read routing. Each enabled family reports exactly one low-cardinality outcome: `no_debt` means the opening status found no work, `useful_completion` means existing debt reached zero inside the budget, `partial_progress` means at least one page was processed before the budget ended with debt remaining, and `no_progress` means the budget or an error produced no processed page. A dark family retains the not-attempted shape with `attempted: false`, `complete: null`, and `outcome: null`. The top-level `outcome` is the worst enabled-family result in the order `no_progress`, `partial_progress`, `useful_completion`, then `no_debt`; `partial_progress` remains healthy, while `no_progress` increments `errors` and makes `ok` false.

Every family summary also copies `oldestOutstandingMarkerAge` from the opening server status instead of deriving age in the sweep. `ageMs` is the oldest age observed in the existing capped repair probe window, and `truncated` says whether unseen markers may include an older one. Track due-work reports `ageMs: null` with `reason: "marker_timestamp_unavailable"` while repair debt exists because `due_work` has no marker-creation timestamp; it never substitutes the mutable `updated_at`. The contract field is optional for rolling compatibility; a caller paired with an older server reports `reason: "status_field_unavailable"` and continues the repair tick. The summary deliberately omits `queue_depth` because capped probes cannot prove an exact remaining depth.

Rebuild, exact audit, and every cutover change remain attended operator operations. The agent token can read bounded status and invoke only the bounded repair action for the four runtime families. It cannot rebuild, audit, mutate a cutover, select another target, change the page limit above the server maximum, or bypass the authenticated control plane.

The service is a one-shot unit, and systemd keeps its timer in the running state until that invocation becomes inactive, so timer firings cannot overlap the same service. Database admission additionally serializes it against other recurring writers. Admission has a 120-second ceiling; the one status process and four possible family processes each have a 120-second ceiling; `TimeoutStartSec=730` covers that 720-second maximum plus fixed process overhead. A timeout is a failed bounded tick rather than a lost cursor: server mutations are page-atomic and the next activation resumes durable debt.

The sweep is visible as `cron.projection-maintenance` on `/status` and as `projections.repair` in the run ledger/admission registry. The status-row message appends the exact top-level outcome, and the ledger preserves the same `outcome` word in `summary_raw`; the normalizer recognizes that low-cardinality field without treating it as a row or subject identifier. Install or refresh the timer through the roster-derived [`../install-host-timers.sh`](../install-host-timers.sh). Rollout is image first, then timer installation, then an attended service start while every cutover is dark; verify a disabled ledger row before relying on the recurring schedule. Roll back by disabling the timer. If projected reads must roll back too, the operator separately closes the affected cutover; never grant the recurring sweep that authority.
